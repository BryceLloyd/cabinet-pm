# Brief 005 — Room Groups + Per-Project Phase Planning

## Goal

Introduce room groups as a hierarchy level within projects (rooms that get installed together), attach per-group phase schedules, and visualize them on a project-scoped Gantt and expandable year plan rows. Task assignment gains a room group FK for Brief 006 readiness.

## Architecture

Room groups are first-class entities (own table, proper FK) that represent installation batches — rooms delivered and installed together. Each room optionally belongs to one group. Phase plans attach date ranges to (group × phase) pairs, forming the per-project schedule. A project-scoped Gantt renders these plans visually. The year plan Gantt gains expandable rows (per-user toggle) showing group sub-bars beneath each project.

## Tech Stack

- Supabase (Postgres migrations, RLS)
- Next.js App Router (server components for data fetching)
- SVG Gantt (extend existing year-plan approach)
- @dnd-kit (already installed — reorder groups)
- date-fns (date math for auto-fill)

## 1. Schema

### 1.1 `room_groups` table

```sql
CREATE TABLE room_groups (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id  uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  name        text NOT NULL,
  sort_order  int  NOT NULL DEFAULT 0,
  notes       text,
  created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX room_groups_project_idx ON room_groups(project_id);
```

RLS: authenticated users can CRUD room_groups (same policy pattern as rooms).

### 1.2 `rooms` alteration

```sql
ALTER TABLE rooms ADD COLUMN room_group_id uuid REFERENCES room_groups(id) ON DELETE SET NULL;
CREATE INDEX rooms_room_group_idx ON rooms(room_group_id);
```

Nullable — existing rooms remain ungrouped. Deleting a group sets affected rooms' `room_group_id` to NULL (not deleted).

### 1.3 `phase_plans` table

```sql
CREATE TABLE phase_plans (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  room_group_id   uuid REFERENCES room_groups(id) ON DELETE CASCADE,
  project_id      uuid REFERENCES projects(id) ON DELETE CASCADE,
  phase_id        uuid NOT NULL REFERENCES phases(id) ON DELETE CASCADE,
  start_date      date NOT NULL,
  end_date        date NOT NULL,
  created_at      timestamptz NOT NULL DEFAULT now(),
  updated_at      timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT phase_plans_one_parent CHECK (
    (room_group_id IS NOT NULL AND project_id IS NULL) OR
    (room_group_id IS NULL AND project_id IS NOT NULL)
  )
);

CREATE INDEX phase_plans_group_idx ON phase_plans(room_group_id);
CREATE INDEX phase_plans_project_idx ON phase_plans(project_id);
CREATE INDEX phase_plans_date_range_idx ON phase_plans(start_date, end_date);
```

Exactly one of `room_group_id` or `project_id` must be set. Group-level plans are the normal case; project-level plans serve as fallback for ungrouped rooms.

RLS: same authenticated pattern as rooms/projects.

### 1.4 `tasks` alteration

```sql
ALTER TABLE tasks ADD COLUMN room_group_id uuid REFERENCES room_groups(id) ON DELETE SET NULL;
CREATE INDEX tasks_room_group_idx ON tasks(room_group_id);
```

Nullable — tasks can now reference a room group. Brief 006 migrates this to a many-to-many join table, but for now a single FK is sufficient.

### 1.5 `profiles` alteration

```sql
ALTER TABLE profiles ADD COLUMN show_room_groups boolean NOT NULL DEFAULT true;
```

Per-user preference controlling whether room group sub-bars appear on year plan Gantt.

### 1.6 Type updates (`lib/types.ts`)


## 3. Project Detail — Planning Section

A new "Planning" section on the project detail page showing a project-scoped Gantt with phase date editing.

### 3.1 Project Gantt

SVG-based Gantt (reuse the year-plan approach — no charting library):

- **X-axis:** Project timeline from `start_date` to `estimated_completion_date`, divided by weeks or months depending on project length
- **Y-axis:** One row per room group + one "Ungrouped" row (if ungrouped rooms exist) + one "Project" row at top showing the overall project bar
- **Phase bars:** Horizontal bars per phase, coloured by `phases.color`, positioned by `phase_plans.start_date/end_date`
- **Today line:** Vertical marker if today falls within the project range

### 3.2 Auto-fill

When the planning section is first opened and no `phase_plans` exist for this project:

1. Fetch active (non-archived) phases ordered by `sort_order`
2. Calculate total project days: `differenceInDays(completion, start)`
3. Distribute phases with equal weight: each phase gets `totalDays / phaseCount` days, rounded
4. Create `phase_plans` entries: one per (group × phase), or (project × phase) if no groups
5. Round to nearest day, skip weekends (Mon–Fri only) for start/end dates

### 3.3 Date editing — table form

Below the Gantt, a table for precise date entry:

| Group | Phase | Start | End |
|-------|-------|-------|-----|
| Kitchen Install | Design | 2026-06-01 | 2026-06-14 |
| Kitchen Install | Production | 2026-06-15 | 2026-07-01 |
| ... | ... | ... | ... |

- Each cell is a date picker (native `<input type="date">`)
- Changes save immediately (debounced) and update the Gantt above
- Soft warning (yellow border) on overlapping or out-of-order phase dates — does not block saving

### 3.4 No visual drag for now

The Gantt is read-only visually. Editing happens in the table form only. Visual drag can be added in a future brief.

### 3.5 Component structure

- `components/projects/project-gantt.tsx` — SVG Gantt rendering
- `components/projects/phase-plan-table.tsx` — editable date table
- `components/projects/planning-section.tsx` — orchestrator that fetches/manages phase_plans, handles auto-fill

## 4. Year Plan Gantt — Expandable Rows

### 4.1 Behaviour

When `profiles.show_room_groups` is ON:
- Each project row gains an expand/collapse chevron on the left of the label
- Clicking expands to show room group sub-bars underneath the project bar
- Sub-bars are indented (label indented ~16px) and shorter height (16px vs 20px)
- Each sub-bar spans from the group's earliest `phase_plan.start_date` to latest `phase_plan.end_date`
- Sub-bar colour: use the phase colour of the group's current leading phase (earliest incomplete phase)
- Collapsed by default — click to expand

When `profiles.show_room_groups` is OFF:
- Year plan behaves exactly as today — no chevrons, no expansion

### 4.2 Data fetching

The plan page query expands to include room groups and phase plans:
```typescript
// In addition to existing project query:
supabase.from("room_groups").select("id, project_id, name, sort_order")
supabase.from("phase_plans").select("id, room_group_id, project_id, phase_id, start_date, end_date")
```

Group into a map keyed by project_id for efficient rendering.

### 4.3 Height calculation

Dynamic — when a project is expanded, total SVG height increases by `(group_count * SUB_ROW_H)` for that project. Other project rows shift down. This recalculates on expand/collapse.

### 4.4 Mobile

Same expand/collapse behaviour. Sub-bars scroll horizontally with the timeline. Labels stack in the sticky left column.

## 7. Constraints & Principles

- Room groups are a hierarchy level, not a tag — proper foreign key
- Ungrouped rooms continue to work — fully backward compatible
- Deleting a room group sets rooms to ungrouped, does not delete rooms
- Soft warning on overlapping/out-of-order phase dates — does not block
- Auto-fill distributes phases across any configured phase set (not hardcoded)
- Year plan expansion is per-user, collapsed by default
- No visual drag on Gantt — table form only for date editing
- Reuse SVG Gantt approach from year-plan, no charting library
