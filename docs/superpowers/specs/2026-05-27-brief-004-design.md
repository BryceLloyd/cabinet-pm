# Brief 004 — Settings Overhaul + Profile + Theme + Density

**Date:** 2026-05-27
**Status:** Design approved, pending implementation
**Depends on:** Brief 002 (completed), Brief 003 (completed)

## Overview

Five phases: (1) restructure settings into URL-routed sections with sidebar nav, (2) profile section with avatar upload and preferences, (3) dark mode via next-themes with full audit of every page, (4) density preference (padding/spacing only), (5) team section with admin role management.

---

## Phase 1: Sectioned Settings Layout

### Current state

- Single flat `/settings` page with all sections stacked vertically in one scroll
- Four components: `BusinessInfoForm`, `SetPassword`, `InviteManager`, `PhaseManager`
- Inline team member list (read-only, no component)
- No URL routing between sections

### Design

**URL structure:**

| Route | Section | Content |
|-------|---------|---------|
| `/settings` | Redirect/list | Desktop: redirects to `/settings/profile`. Mobile: shows section list |
| `/settings/profile` | Profile | Name, avatar, email, password, theme, density, sign out |
| `/settings/business` | Business | Business info form (name, email, phone, address, logo, workshop photo) |
| `/settings/team` | Team | Team member list + admin role management + allowed emails |
| `/settings/phases` | Phases | PhaseManager (existing) |

**Desktop layout (md+):**
- Left sidebar (w-56) with section links, styled as vertical nav
- Active section highlighted with `bg-muted` and `font-medium`
- Content area fills remaining width, max-w-2xl
- Settings layout wraps both sidebar and content in a `flex` container

**Mobile layout (<md):**
- `/settings` shows a drill-in list: section name + chevron right, stacked vertically
- Tapping a section navigates to `/settings/profile` etc. — shows full-screen content
- Back navigation: "← Settings" link at top of each section page (mobile only)
- No sidebar visible on mobile

**Implementation approach:**
- New `app/(app)/settings/layout.tsx` — settings shell with sidebar + `{children}`
- New `app/(app)/settings/page.tsx` — redirect to `/settings/profile` on desktop, section list on mobile
- Each section: `app/(app)/settings/profile/page.tsx`, `app/(app)/settings/business/page.tsx`, `app/(app)/settings/team/page.tsx`, `app/(app)/settings/phases/page.tsx`
- Existing components migrate unchanged to their new section pages

**Settings sidebar nav items:**

```tsx

  { href: "/settings/profile", label: "Profile", icon: User },
```

## Phase 2: Profile Section

### Current state

- No profile editing UI exists — only the user menu shows name/email/role
- `SetPassword` component exists but lives in the flat settings page
- `profiles` table has: `id`, `full_name`, `avatar_url`, `role`, `created_at`
- No theme, density, or notification preference columns

### Schema change

New migration `009_profile_preferences.sql`:

```sql
alter table profiles add column theme_preference text default 'system'
  check (theme_preference in ('light', 'dark', 'system'));
alter table profiles add column density_preference text default 'comfortable'
  check (density_preference in ('compact', 'comfortable'));
alter table profiles add column notification_preferences jsonb default '{}'::jsonb;
```

- `theme_preference`: `'light'`, `'dark'`, or `'system'` (default: `'system'`)
- `density_preference`: `'compact'` or `'comfortable'` (default: `'comfortable'`)
- `notification_preferences`: empty jsonb for now — placeholder for Brief 007

**Update `Profile` type in `lib/types.ts`:**

```ts
export interface Profile {
  id: string;
  full_name: string;
  avatar_url: string | null;
  role: "admin" | "member";
  theme_preference: "light" | "dark" | "system";
  density_preference: "compact" | "comfortable";
  notification_preferences: Record<string, unknown>;
  created_at: string;
}
```

### Profile page design

**Sections on `/settings/profile`:**

1. **Avatar + name** — circular avatar preview (96px), upload button (Supabase Storage bucket `avatars`), full name input. Save button.
2. **Email** — read-only display of the user's auth email
3. **Appearance** — theme toggle (three-option segmented control: Light / Dark / System) + density toggle (two-option: Comfortable / Compact). Changes save immediately to Supabase (no save button).
4. **Password** — existing `SetPassword` component, moved here
5. **Sign out** — button at bottom, calls `supabase.auth.signOut()`

**Avatar upload:**
- Same pattern as business logo upload in `BusinessInfoForm`
- Supabase Storage bucket: `avatars`
- Path: `avatars/{user_id}` (overwrite on re-upload)
- On success: update `profiles.avatar_url` with public URL
- Preview updates immediately (optimistic)

### Files

- **Create:** `components/settings/profile-form.tsx` — client component, name/avatar/appearance/password/signout
- **Modify:** `lib/types.ts` — add preference fields to Profile
- **Create:** `supabase/migrations/009_profile_preferences.sql`

## Phase 3: Theme Support + Dark Mode Audit

### Current state

- `tailwind.config.ts` has `darkMode: ["class"]` — class-based toggling ready
- `globals.css` has full `.dark` variable set already defined
- `app/layout.tsx` has `suppressHydrationWarning` on `<html>` — ready for next-themes
- No `next-themes` installed, no ThemeProvider

### Design

**next-themes integration:**

1. Install `next-themes`
2. Create `components/theme-provider.tsx` — thin wrapper around `ThemeProvider` from next-themes with `attribute="class"`, `defaultTheme="system"`, `enableSystem`, `disableTransitionOnChange`
3. Wrap `{children}` in root `app/layout.tsx` inside `<ThemeProvider>`
4. On profile load: read `theme_preference` from DB → call `setTheme()` to sync
5. On preference change: update DB + call `setTheme()` in one action

**Theme toggle in user menu:**
- New `ThemeMenuItem` sub-component inside user-menu
- Three-state cycle: system → light → dark → system
- Shows current theme icon (Sun/Moon/Monitor) + label
- Uses `useTheme()` from next-themes
- Also saves preference to Supabase `profiles.theme_preference`

**Theme toggle in profile settings:**
- Three-option segmented control (Light / Dark / System)
- Uses same `useTheme()` hook
- Also saves to Supabase

**Dark mode audit — required pages:**

Every page must render correctly in dark mode. Key areas to check:

| Page | Likely issues |
|------|---------------|
| Dashboard | Card backgrounds, chart colours |
| Plan (year view) | Gantt bars, calendar grid borders, month headers |
| Projects list | Phase badge colours on dark bg |
| Project detail | Room cards, task list borders |
| Tasks | Tab indicators, checkbox styling |
| Settings (all sections) | Form inputs, section cards |
| Login | Background, input borders |

**Common fixes expected:**
- Replace hardcoded `bg-white` → `bg-card` or `bg-background`
- Replace hardcoded `text-gray-*` → `text-muted-foreground` or semantic tokens
- Replace hardcoded `border-gray-*` → `border` (uses `--border` token)
- Check inline `style` attributes for hardcoded colours
- Ensure Radix UI popovers/dropdowns use `bg-popover` token

### Files

- **Create:** `components/theme-provider.tsx` — next-themes wrapper
- **Modify:** `app/layout.tsx` — wrap in ThemeProvider
- **Modify:** `components/user-menu.tsx` — add theme toggle menu item
- **Modify:** Multiple files during dark mode audit (exact list determined during implementation)
- **Modify:** `package.json` — add `next-themes`

## Phase 4: Density Preference

### Design

**CSS custom properties approach:**

Add density variables to `globals.css`:

```css
:root {
  --density-card-padding: 1.5rem;   /* 24px — comfortable */
  --density-row-padding: 0.75rem;   /* 12px */
  --density-gap: 1.5rem;            /* 24px */
  --density-section-gap: 2rem;      /* 32px */
}

.density-compact {
  --density-card-padding: 1rem;     /* 16px — compact */
  --density-row-padding: 0.375rem;  /* 6px */
  --density-gap: 0.75rem;           /* 12px */
  --density-section-gap: 1rem;      /* 16px */
}
```

**Application strategy:**
- `density-compact` class toggled on `<html>` alongside the `dark` class
- A `DensityProvider` component reads the preference from the profile and applies the class
- Key areas that consume density variables:
  - Dashboard cards: padding
  - Task list rows: vertical padding
  - Project detail sections: gaps between rooms/tasks
  - Settings form sections: spacing
  - Table-like displays: row height

**Font sizes do NOT change** — only padding and spacing.

**Density toggle in profile:**
- Two-option segmented control: Comfortable / Compact
- Changes save immediately to Supabase + apply class to `<html>`

### Files

- **Create:** `components/density-provider.tsx` — reads preference, applies class
- **Modify:** `app/layout.tsx` — wrap in DensityProvider
- **Modify:** `app/globals.css` — add density CSS variables
- **Modify:** Key components to use `var(--density-*)` instead of hardcoded padding values

## Phase 5: Team Section

### Current state

- Settings page has an inline team member list (just name + role badge, read-only)
- `InviteManager` component handles the allowed emails CRUD
- No ability to change a member's role

### Design

**Team page layout (`/settings/team`):**

1. **Team members** — list of all profiles
   - Each row: avatar (32px circle), full name, email, role badge
   - Admin view: role is a `<select>` dropdown (admin / member) — change saves immediately
   - Non-admin view: role is a read-only badge
   - Cannot change your own role (prevent self-demotion)

2. **Allowed emails** — `InviteManager` component (admin-only, unchanged)
   - Moved from the flat settings page to below the team list
   - Same functionality: add email + role, remove

**No changes to InviteManager itself** — it's just relocated.

### Files

- **Create:** `components/settings/team-list.tsx` — team member list with admin role editing
- **Modify:** `app/(app)/settings/team/page.tsx` — renders team list + InviteManager

## Principles

- next-themes for battle-tested SSR theme support — no custom flash prevention needed
- Dark mode is mandatory — brief not done until every page renders cleanly
- Density is padding/spacing only — no font size changes
- Preferences save to Supabase immediately (no explicit save button for appearance)
- `notification_preferences` column added now to avoid future migration (Brief 007)
- Existing components (`BusinessInfoForm`, `SetPassword`, `InviteManager`, `PhaseManager`) migrate to new routes without modification
- Settings sidebar follows same visual language as the main app header nav

## Out of scope

- Notification preferences UI (Brief 007)
- Custom colour themes beyond light/dark
- Per-section admin gating on sidebar (all sections visible; admin-only features gated inside each section)
- Avatar cropping or resizing — upload as-is, CSS `object-cover` for display
