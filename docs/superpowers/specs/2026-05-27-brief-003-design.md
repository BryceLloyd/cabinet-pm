# Brief 003 — Mobile FAB + Phase Management UI

**Date:** 2026-05-27
**Status:** Design approved, pending implementation
**Depends on:** Brief 002 (completed)

## Overview

Two phases: (1) a context-aware mobile floating action button with Vaul drawer for quick-add forms, and (2) an admin-only phase management UI in Settings with drag-to-reorder, colour picker, and soft-delete via `archived_at`.

---

## Phase 1: Mobile FAB (Floating Action Button)

### Current state

- Projects page has a "New project" link button (both mobile and desktop)
- Tasks page has a "+ Add task" toggle button that expands an inline form
- Project detail has inline "Add room" input and "Add task" fields
- Dashboard has no create actions
- No shared mobile quick-add pattern exists

### Design

**FAB button:**
- Pill-shaped, primary colour (`bg-primary text-primary-foreground`)
- Fixed position, horizontally centered, sits 12px above the bottom tab bar
- Position: `fixed bottom-[calc(72px+env(safe-area-inset-bottom)+12px)] left-1/2 -translate-x-1/2 z-50`
- Mobile only: `md:hidden`
- Icon: `Plus` (lucide) + contextual label text
- Shadow for elevation: `shadow-lg`
- Height: `h-11` (44px, good tap target)

**Per-page behaviour (determined by `usePathname()`):**

| Route | FAB label | Action |
|-------|-----------|--------|
| `/dashboard` | + Add | Opens drawer with picker: "New project" / "New task" |
| `/plan` | + New project | Navigates to `/projects/new` (no drawer) |
| `/projects` | + New project | Navigates to `/projects/new` (no drawer) |
| `/projects/[id]` | + Add | Opens drawer with picker: "Add room" / "Add task" |
| `/tasks` | + New task | Opens drawer with quick task form |
| `/settings` | — | FAB hidden |

**Vaul drawer (bottom sheet):**
- Uses `vaul` library (new dependency)
- Slides up from bottom with drag handle
- Swipe-to-dismiss built in
- Overlay backdrop (`bg-black/40`)
- Content: depends on page context (picker or form)

**Drawer content — Dashboard picker:**
- Two large tap-target buttons stacked vertically
- "New project" → navigates to `/projects/new`, closes drawer
- "New task" → switches drawer content to quick task form

**Drawer content — Project detail picker:**
- "Add room" → shows single text input + "Add" button (inserts room via Supabase, refreshes)
- "Add task" → shows quick task form scoped to current project

**Drawer content — Quick task form (Tasks page & project detail):**
- Fields:
  - Title (text input, required, autofocus)
  - Project (select, optional — "Personal todo" default; pre-selected when opened from project detail)
  - Assignee (select, optional — disabled when personal; pre-selected to current user)
  - Due date (date input, optional)
- "Add task" submit button (`bg-primary`)
- On success: close drawer, `router.refresh()` to reload server data
- Mirrors existing `TasksClient.addTask()` logic

**Context passing:**
- The FAB needs the current project ID when on `/projects/[id]` pages
- Solution: `MobileFab` reads `usePathname()` to extract the project ID from the URL segment
- For the task form, project options and profile options are needed — these are fetched client-side from Supabase when the drawer opens (lightweight queries, cached in state)

**Desktop behaviour:**
- FAB is completely hidden on desktop (`md:hidden`)
- Existing desktop buttons remain unchanged

### Files

- **Create:** `components/mobile-fab.tsx` — FAB button component with route-aware label/action logic
- **Create:** `components/mobile-fab-drawer.tsx` — Vaul drawer wrapper with all form variants (picker, quick task, add room)
- **Modify:** `app/(app)/layout.tsx` — add `<MobileFab />` after `<BottomTabBar />`
- **Modify:** `package.json` — add `vaul` dependency

## Phase 2: Phase Management UI

### Current state

- Settings page shows phases in a read-only `<ul>` list
- Each row: colour swatch (3x3 rounded-sm), name, "default" badge, sort order number
- All users see the phases section (not admin-gated)
- No add/edit/delete/reorder functionality
- `Phase` type: `{ id, name, sort_order, color, is_default, created_at }`

### Schema change

New migration `008_phases_archived_at.sql`:

```sql
alter table phases add column archived_at timestamptz;
```

- Nullable — all existing phases remain active (`archived_at = null`)
- All existing phase queries throughout the app must add `where archived_at is null` filter (or the equivalent `.is("archived_at", null)` in Supabase JS)
- The phase manager settings view shows archived phases separately (greyed out, with "Restore" option)

**Affected queries (need `.is("archived_at", null)` filter added):**
- `app/(app)/settings/page.tsx` — phases fetch for the settings page (phase manager handles its own queries separately)
- `app/(app)/projects/page.tsx` — phases fetch for project list phase badges
- `app/(app)/projects/[id]/page.tsx` — phases fetch for project detail phase selector
- `app/(app)/projects/new/page.tsx` — phases fetch for default phase lookup
- `app/(app)/plan/page.tsx` — phases fetch for year plan view
- `components/dashboard/cards/projects-by-phase-card.tsx` — phases fetch for phase distribution card
- `components/dashboard/cards/upcoming-deadlines-card.tsx` — phases fetch for deadline card phase badges

### Phase manager UI

**Admin view — `PhaseManager` client component:**

Replaces the read-only phases `<ul>` for admin users. Non-admins continue to see the read-only list.

**Default state (not editing):**
- Same visual as current: colour swatch, name, default badge, sort order
- "Edit phases" button in the section header (admin only)

**Edit mode (admin clicks "Edit phases"):**
- Header changes to "Edit phases" with a "Done" button
- Each phase row becomes interactive:
  - **Drag handle** (left, via @dnd-kit `useSortable`) — `GripVertical` icon
  - **Colour swatch** (clickable) — opens colour picker popover
  - **Name** — editable text input (inline)
  - **Default radio** — radio button, only one phase can be default
  - **Archive button** (right) — `Archive` icon, greyed for default phase (can't archive the default)

**Colour picker popover:**
- Uses Radix Popover (already installed)
- Grid of 16 preset Tailwind colours:
  - `#ef4444` (red-500), `#f97316` (orange-500), `#f59e0b` (amber-500), `#eab308` (yellow-500)
  - `#84cc16` (lime-500), `#22c55e` (green-500), `#14b8a6` (teal-500), `#06b6d4` (cyan-500)
  - `#3b82f6` (blue-500), `#6366f1` (indigo-500), `#8b5cf6` (violet-500), `#a855f7` (purple-500)
  - `#d946ef` (fuchsia-500), `#ec4899` (pink-500), `#f43f5e` (rose-500), `#78716c` (stone-500)
- Each swatch is a 24x24 rounded circle button
- Currently selected colour has a ring/check indicator
- Selecting a colour immediately saves to Supabase (optimistic update)

**Add phase:**
- "Add phase" button at bottom of the list in edit mode
- Creates a new phase with: name "New phase", colour random from palette, sort_order = max + 1, is_default = false
- Row appears immediately in edit mode for inline name editing

**Drag to reorder:**
- Uses `@dnd-kit/core` + `@dnd-kit/sortable` (already installed from Brief 002)
- `SortableContext` wraps the phase list
- On drag end: recalculate `sort_order` values (0-indexed), batch update to Supabase
- Optimistic UI — list reorders immediately, reverts on error

**Set default:**
- Clicking the radio button on a non-default phase:
  1. Unsets `is_default` on the current default phase
  2. Sets `is_default` on the selected phase
  3. Both updates in a single Supabase call (or two sequential calls)
  4. Optimistic update in UI

**Archive flow:**
- Clicking archive on a phase triggers a check: how many rooms currently have `current_phase_id` = this phase?
- If count > 0: show Radix AlertDialog — "X rooms are currently in the '[phase name]' phase. Archiving won't remove them, but this phase won't be available for new assignments. Archive anyway?"
- If count = 0: archive immediately (no confirmation)
- Archive action: `update phases set archived_at = now() where id = ?`
- Archived phases disappear from the active list and appear in a collapsed "Archived" section below (if any exist)

**Archived section:**
- Collapsed by default (disclosure arrow)
- Shows archived phases greyed out with a "Restore" button
- Restore: `update phases set archived_at = null where id = ?`

**Non-admin view:**
- Unchanged from current — read-only list of active phases
- No "Edit phases" button

## Principles

- Mobile-first for the FAB — desktop UI unchanged
- Vaul for native-feeling bottom sheets with swipe-to-dismiss
- Preset Tailwind colour palette only — no custom hex input
- Non-admins see read-only phases
- Soft delete preserves phase history (rooms keep their `current_phase_id` reference)
- @dnd-kit reuse from Brief 002 for phase reorder
- Schema migration is a simple nullable column add — zero risk to existing data

## Out of scope

- Project creation form inside the drawer (FAB navigates to `/projects/new` for full form)
- Phase usage analytics or reporting
- Supabase realtime subscriptions for phase changes
- Dark mode (Brief 004)
