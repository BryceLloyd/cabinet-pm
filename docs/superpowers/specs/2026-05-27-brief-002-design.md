# Brief 002 — Header Restructure, Bigger Mobile Tabs, Dashboard Cards

**Date:** 2026-05-27
**Status:** Design approved, pending implementation
**Depends on:** Brief 001 (deployed)

## Overview

Four phases that make the app feel personal (business name in header), give users control over their dashboard, and fix mobile tap-target sizing. No schema migrations — dashboard layouts use localStorage with a clear interface for later Supabase swap.

---

## Phase 1: Header Restructure

### Current state

- Header: logo + business name (left), desktop nav (middle), avatar (right)
- Business name hidden on mobile (`hidden md:inline`)
- Dashboard page body duplicates business name + logo above its own `<h1>`
- Every page has its own `<h1>` heading block in the page body

### Changes

**Header becomes:** Logo + Business Name + Page Title inline, avatar top-right, desktop nav between.

Layout: `[Logo] [BizName] [PageTitle]  ...  [Nav links]  [Avatar]`

- Business name: visible on desktop, hidden on mobile (unchanged)
- Page title: new addition, shown on all screen sizes
- Separator between biz name and page title: a subtle `/` or `|` on desktop; on mobile just the page title since biz name is hidden
- Remove standalone heading blocks from page bodies (dashboard, settings, tasks, projects, plan)

**Implementation approach — page title:**

Use a client component `PageTitle` that reads from `usePathname()` and maps routes to titles:

```
/dashboard     → "Dashboard"
/plan          → "Year Plan"
/projects      → "Projects"
/projects/[id] → "Project" (or fetched project name if feasible)
/projects/new  → "New Project"
/tasks         → "Tasks"
/settings      → "Settings"
```

This avoids prop-drilling through the server layout. The `PageTitle` component renders inline in the header.

### Files changed

- `app/(app)/layout.tsx` — header restructure, add PageTitle, remove `<h1>` pattern
- `components/page-title.tsx` — new client component
- `app/(app)/dashboard/page.tsx` — remove heading block
- `app/(app)/settings/page.tsx` — remove heading block
- `app/(app)/tasks/page.tsx` — remove heading block (if present)
- `app/(app)/projects/page.tsx` — remove heading block (if present)
- `app/(app)/plan/page.tsx` — remove heading block (if present)

## Phase 3: Dashboard Cards Infrastructure

### Card registry

A `CARD_REGISTRY` object in `lib/dashboard/card-registry.ts`:

```ts
type CardDefinition = {
  type: string;           // e.g. "my_tasks"
  title: string;          // default display title
  description: string;    // shown in "add card" picker
  component: () => Promise<{ default: React.ComponentType }>;  // lazy import
  defaultSize: "sm" | "lg";  // 1-col or 2-col on desktop
};
```

Each card component is registered here. Adding a new card = adding one entry + one component file.

### DashboardCard wrapper

Base component providing consistent chrome:

- Rounded border, `bg-card`
- Header row: title (left) + optional action link (right, e.g. "View all")
- Content area (children)
- In edit mode: shows `x` remove button top-right

### Layout persistence (localStorage)

`lib/dashboard/dashboard-layout.ts`:

```ts
type CardLayout = {
  cardType: string;
  position: number;
};

function getLayout(userId: string): CardLayout[]
function setLayout(userId: string, layout: CardLayout[]): void
function getDefaultLayout(): CardLayout[]
```

Storage key: `cabinet-pm-dashboard-{userId}`

Default layout (seeded on first load):
1. `my_tasks` (position 0)
2. `upcoming_deadlines` (position 1)
3. `projects_by_phase` (position 2)

**Interface designed for later Supabase swap:** When we add the `dashboard_layouts` table, we replace `getLayout`/`setLayout` internals. Nothing else changes.

### Edit mode

- Toggle button in dashboard header area: "Customise" / "Done"
- When active:
  - Each card shows a remove (x) button
  - An "Add card" button appears at the end of the grid, opening a popover/dialog listing available cards not already in the layout
- When inactive: normal dashboard view

### Grid layout

- Mobile: `grid-cols-1`
- Desktop: `grid-cols-2` (`lg:grid-cols-2`)
- Cards with `defaultSize: "lg"` span 2 columns on desktop (`lg:col-span-2`)
- Gap: `gap-4` on mobile, `gap-6` on desktop

### Lazy loading

Each card loaded via `React.lazy()` + `<Suspense>` with a skeleton card fallback (pulse animation matching card dimensions).

### New dependency

`@dnd-kit/core` + `@dnd-kit/sortable` — installed in this phase, used for drag-to-reorder cards in edit mode. Keeps card reordering smooth without custom drag logic.

### Files created

- `lib/dashboard/card-registry.ts` — registry + types
- `lib/dashboard/dashboard-layout.ts` — localStorage persistence
- `components/dashboard/dashboard-card.tsx` — base card wrapper
- `components/dashboard/dashboard-grid.tsx` — grid container + edit mode logic
- `components/dashboard/add-card-dialog.tsx` — card picker for edit mode

## Phase 4: Dashboard Card Components

Six card types, all reading from existing Supabase tables:

### my_tasks

- Query: `tasks` where `assigned_to = user.id` and `completed_at is null`, ordered by `due_date`, limit 20
- Display: task title, project name, room name, due date with overdue highlighting
- Action link: "View all" → `/tasks`
- Default size: `sm` (1-col)

### upcoming_deadlines

- Query: `projects` where `estimated_completion_date` is within next 14 days, ordered ascending
- Display: project name, client, completion date, phase badge
- Action link: "View all" → `/projects`
- Default size: `sm` (1-col)

### projects_by_phase

- Query: `projects` (active/planning) + `phases`
- Display: horizontal bar or list showing count of projects per phase, colour-coded with phase colours
- No action link
- Default size: `sm` (1-col)

### team_workload

- Query: `tasks` (not completed) joined with `profiles`, grouped by assignee
- Display: team member name + avatar/initials, open task count, sorted descending
- No action link
- Default size: `sm` (1-col)

### personal_todos

- Query: `tasks` where `assigned_to = user.id`, `project_id is null`, `completed_at is null`
- Display: simple task list with checkbox to complete
- Action link: "View all" → `/tasks?filter=personal`
- Default size: `sm` (1-col)

### notes

- No Supabase query — localStorage only
- Storage key: `cabinet-pm-notes-{userId}`
- Display: textarea with auto-save (debounced 500ms)
- Default size: `sm` (1-col)

### Files created

- `components/dashboard/cards/team-workload-card.tsx`
- `components/dashboard/cards/personal-todos-card.tsx`
- `components/dashboard/cards/notes-card.tsx`

### Files changed

- `app/(app)/dashboard/page.tsx` — replaced with server component that fetches user ID + passes to client `DashboardGrid`

## Principles (from roadmap)

- One new dependency only (`@dnd-kit`)
- Card components must be lazy-imported
- Mobile-first dashboard grid, test at 375px
- Personal data (dashboard layouts) is per-user — localStorage keyed by userId, later RLS via Supabase

- Supabase `dashboard_layouts` table (deferred — localStorage fallback for now)
- Dark mode (Brief 004)
- Mobile FAB (Brief 003)
- Any new Supabase schema migrations
